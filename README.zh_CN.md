## PDKPASS 能做什么

PDKPASS 将 AI Passport 变成离线优先的 F1 随身伴侣：打开就能看到当前或下一站，
还可以浏览全年赛历、车手积分、赛道详情，以及各个比赛分节的前三名。

- 按北京时间自动选择当前或下一站，无需手动切换日期。
- 每站使用独立配色，同时让首页、赛历、详情、积分、成绩、配网和赛季结束页面保持
  同一套赛车通行证视觉语言。
- 内置 2026、2027 赛历和每站不同的赛道轮廓，首次离线也能使用。
- 联网后下载当前赛季与积分榜，并将最后一次有效数据留在设备中供离线查看。
- 成绩可覆盖 FP1、FP2、FP3、冲刺排位、冲刺赛、排位赛与正赛，并缓存各分节前三名。
- 闲置后自动降低亮度并关闭背光。

## 不需要安装手机 App

不需要安装手机 App。在首页长按 OK 打开 `NETWORK`，选择 `WI-FI SETUP`；
已经联网时需要再确认。设备先扫描附近网络，再开启临时热点并显示二维码。
短按 OK 可切换到备用信息页，查看热点名称、密码和 `192.168.9.1`。

每次开启都会重新生成八位 WPA2 密码，使用大写字母和数字，不含 `I`、`O`、`0`、`1`。

1. 用手机扫描二维码并加入设备热点；扫码不便时，可按备用页的信息手动连接。
2. 在手机浏览器打开 `http://192.168.9.1`。
3. 从附近真实的 2.4 GHz 网络中选择一个，或手动填写网络名称；输入密码后按 **Connect**。

PDKPASS 会先验证连接，成功后才保存凭据。密码错误时配网页会继续保留，可以重新填写。
最多记住 5 个网络，关机不丢失；优先连接上次成功的网络。开机和断线时扫描一次，
只尝试发现的已保存网络，每个最多两次、每次最多 15 秒。没有保存网络就不扫描。
全部失败后关闭 Wi-Fi，不开热点、不周期重试。选择 `RETRY WI-FI` 才再次扫描，
这个操作不会开启热点，也不会打断正常连接。

配网热点连续三分钟没有手机连接即关闭，从开启起最多保留十分钟，手机重连或重复
提交不会重置上限。验证连接时暂停无人连接检查，但十分钟上限仍然有效。获取 IP
并保存成功后立即关闭热点，校时另行进行。长按 OK 可取消重试或关闭热点，屏幕
仍然正常自动调暗、熄灭。

添加网络时，主动从菜单进入配网即可。同名 Wi-Fi 更新
密码；第 6 个不同名称的网络会替换最久未成功连接的网络。错误密码不会覆盖原有凭据。
仅加载当前版本的网络列表，不再导入旧固件的单网络凭据；不需要手机 App。
浏览器从 `0x0` 写入合并固件会覆盖 NVS，刷写后需要重新配网。

顶部状态会依次显示 `SETUP`、`WIFI...`、`TIME...` 和 `WIFI OK`。`WIFI OK` 只代表
网络已连接，不代表赛历或成绩已经更新。网络菜单分别显示当前赛季 `CAL SYNC`（赛历）、
`RESULTS`（成绩）、`DRIVERS`（车手积分）和 `TEAMS`（车队积分）成功检查的北京时间日期。
手动和自动查询都在完整响应验证通过、变更数据保存成功后更新对应日期；数据无变化也算成功检查。
积分部分成功时只记录成功的表，积分查询不会修改赛历日期。保留旧的赛历和成绩日期，
每类数据每天最多写一次日期。其他赛季的日期不会冒充本赛季状态，
未同步新赛季时显示 `CAL 2027 NO SYNC` 或 `RESULT 2027 NO SYNC`。本赛季有缓存但日期
未记录时显示 `CACHE DATE?`；既无缓存也无更新记录时显示 `NEVER`。时间同步后，
设备会自行计时，并在北京时间每天 00:00、当前分站的切换点，以及网络恢复后检查
赛季数据。联网赛历会在记录的正赛结束后自动切换到下一站；内置离线回退赛历则使用
计划正赛发车后 4 小时作为切换点。最后一站结束后显示 `SEASON COMPLETE`。

## 场次提醒

默认开启提醒。在 `NETWORK` 中选择 `ALERTS: ON/OFF`，短按 OK 切换，设置会保存。
实际安排的 FP1、FP2、FP3、冲刺排位、冲刺赛、排位赛和正赛，均在开始前十分钟
提醒一次。不存在或已取消的场次不提醒；同步到的改期会更新提醒时间。
同一开关也控制场次成绩首次保存成功时的提示音；关闭 `ALERTS` 后按键音仍可播放。

使用已确认的三秒铃声，音量 80%，按键音保持 50%。音频初始化或打开失败后，
至少间隔 60 秒，在收到新提示音请求时重试；失败的提示不会延后补响。提醒会亮屏最多十五秒，显示
分站、场次和开赛时间。任意键停止并关闭提醒，不触发导航。随后恢复原页面；
原本熄屏时，会恢复休眠。

复用现有场次后台同步，将接口给出的准确开始时间缓存到本地，无需进入成绩页。
已校时且已缓存赛程时，断网、熄屏和轻睡眠仍可提醒。完全断电重启后需要重新
校时；彻底关机无法响铃。首次下载若遭遇接口失败或实时赛事期间的认证限制，
可能拿不到提醒所需时间，不会用猜测的时间替代。

若在开赛前十分钟内才同步成功，会补提醒一次；已开赛则不补响。响铃前持久化
已提醒的场次 ID，避免重连或重启重复提醒；保存失败则等待五秒后重试。如果
在保存成功与实际响铃之间断电，该次提醒可能被跳过。定时复用现有后台任务，
不新增任务，也不每秒请求网络。真实响度、唤醒、耗电以及 TLS 与音频同时运行
时的内存余量，仍需实机验证。

## 省电策略

30 秒无操作后调暗，90 秒后关闭背光并让 LCD 控制器休眠。熄屏时暂停绘图和画面失效刷新，时钟及
北京时间切站定时器继续运行。手动同步轮询在熄屏时暂停，按键或提醒成功唤醒后立即读取最新状态。
第一次按键只唤醒，不切换页面。ADC 按键仍每
20 毫秒扫描一次，不依赖尚未验证的 GPIO 唤醒阈值，不使用深睡眠。
亮屏时每分钟读取一次电量计；熄屏后暂停读取，按键唤醒时立即补读一次。
在首页浏览其他分站时，选择会保留到 90 秒无操作熄屏；下次唤醒回到当周比赛。
电量未变化时不重绘电池图标。

亮屏时 CPU 保持 160 MHz，熄屏空闲时可降至 40 MHz 并自动进入轻睡眠。
配网、连接网络期间及 USB 控制台连接时禁止轻睡眠。LVGL 直接读取单调时钟，
不再依靠每 5 毫秒一次的计时中断。

校时成功后，每 30 秒检查联网是否空闲。两个数据任务在未来一分钟内都没有工作，
且没有进行中的 HTTP 事务时，关闭无线电。任务的实际截止时间（每日更新、赛后
成绩或失败退避）会触发重新联网。历史补齐或即将到期的工作保持连接，避免反复
握手。因此，更新成功后显示 `WIFI OFF` 是正常的；打开未缓存的赛道详情或成绩
也可唤醒这种主动休息的网络连接。

自动唤醒只适用于主动省电断网。已保存网络全部失败、开机首次校时超时（60 秒）
或手动取消后保持离线，直到手动重试、配网或重启。热点超时规则不变。连接 USB
时测出的电流不代表电池待机；实际电流、ADC 响应和唤醒可靠性仍需真机验证。

## 分节成绩

分节结束后，打开对应分站详情并按确定键，即可浏览 FP1、FP2、FP3、冲刺排位、
冲刺赛、排位赛和正赛成绩。PDKPASS 会等待记录的分节结束时间至少 30 分钟，再查询
前三名；后台采用低频重试，因此免费成绩通常会在结束后约 30–40 分钟出现，缓存成功后
可离线查看。成绩页只浏览该站安排的分节：普通周末跳过冲刺排位和冲刺赛，
冲刺周末跳过 FP2、FP3。场次信息尚未同步时使用内置赛历的周末类型，
同步后以下载的场次信息为准。已安排但成绩尚未获取的分节仍显示，取消的场次保留说明。
主动打开分站成绩或从该页面唤醒设备后，该站在后续各分节下载中持续优先；
失败五分钟后重试，不必等待后台省电补齐任务的较长间隔。选择另一分站会转移
优先级，已缓存的前三名不重复下载。
手动优先级在最后一次请求后 15 分钟到期，避免无人操作时历史分站仍永久每五分钟
重试；到期后历史成绩恢复每日重试，当周比赛仍保留自动获取成绩。
在成绩页短按 OK，只重新查询当前显示的赛段，包括已缓存但后来更正的成绩；其他赛段保持不变。
页脚显示同步结果；失败时保留原有成绩。重复手动请求间隔至少 60 秒。受理后总超时为 120 秒，
包括等待共享 HTTP 的时间；超时显示 `SYNC TIMEOUT`。
下载的成绩保存失败时，保留待保存状态，60 秒后重试本地写入，断网时也继续重试。
共享事务忙时等待可用后再试；保存成功后停止本地重试。手动同步仍显示本次保存失败，
成功保存前断电仍可能丢失待保存的更改。

历史分节名次与车手资料来自非官方的
[OpenF1 API](https://openf1.org/docs/)。PDKPASS 使用无需身份验证的历史接口，不会在
固件中写入 OpenF1 账号、密码或访问令牌。

## 赛季数据与离线行为

首次使用的内置赛历，是 2026 年 8 月 31 日获取的离线快照，来源为
[F1 官方 2026 赛历](https://www.formula1.com/en/racing/2026)。页面中的比赛
时间已转换为中国标准时间（UTC+8）。车手积分不再加载内置默认分数：没有接口缓存时
显示 `CONNECT TO UPDATE` 和 `DRIVER DATA PENDING`，同步成功后保存供离线查看。
同一固件镜像重启继续使用缓存；换镜像后首次启动，在后台任务启动前清空已下载赛历、
车手和车队积分、成绩及其同步日期，然后重新获取。不再导入默认 NVS 的旧缓存，
Wi-Fi、时钟和提醒设置保持不变。

第一次成功联网后，PDKPASS 会下载并保存当前北京时间年份的 Grand Prix 赛历，以及
Jolpica 最新发布的车手积分。本次开机成功校时后，到北京时间新年会选择较新的内置赛季，
无需 Wi-Fi 或 HTTPS 成功；离线任务也会在北京时间零点检查。同年或更新年份的联网
缓存优先于内置版本，未来年份没有内置数据时保留最后有效赛季。
Flash 同时包含两年的内置赛历，运行内存和下载缓存只保留一个活动赛季，
最多包含 24 场比赛、24 名车手及 7 类分节的前三名。

2027 内置赛历按
[9 月 16 日官方公告](https://corp.formula1.com/2027-calendar-announced-with-10-sprint-events/)
收录 24 站和 10 个冲刺周末。日期是举办地日期，未公布的具体时间显示 `TIME TBD`，
不编造时间、圈数、车手或积分。尚未取得分节资料时，以举办地最后一个比赛日期过后的
当地零点作为日期级切站边界，并非实际正赛结束时间；联网分节结束时间会替换该边界。
伊斯坦布尔仍以通过 FIA 赛道认证为前提。同赛道保持已有配色。
OpenF1 赛历与成绩数组逐条处理。Jolpica 积分每页下载四位车手，单次响应限制 4 KB，
并限制请求频率。所有页面的赛季、轮次与总人数必须一致；不完整或无效响应保留旧积分
及日期。真机内存和 TLS 表现仍待验证。

最近一次有效时间、已确认赛季、积分榜和已下载的前三名都会保留供离线查看。如果设备
长时间彻底断电，重新联网后即可刷新。车手积分及其姓名、车队资料仅从
[Jolpica](https://github.com/jolpica/jolpica-f1/blob/main/docs/endpoints/driverStandings.md) 获取，
赛历和各场次成绩继续使用 [OpenF1](https://openf1.org/docs/)。
OpenF1 赛历失败不会阻止同赛季 Jolpica 积分更新，两个来源分别处理限流退避。
完整积分校验并保存成功后才更新显示。同一赛季代表多个车队的车手显示 `MULTIPLE TEAMS`，
因为接口数组顺序不能确定其当前车队。

首页长按下键打开 `TEAM POINTS` 车队积分，长按上键打开车手积分。
上下键滚动排名，长按 OK 返回首页；短按 OK 同时刷新车手和车队积分，
不重新下载赛历。同步期间保留现有排名，页脚显示结果；重复请求间隔至少 60 秒。受理后总超时为 120 秒，
包括等待共享 HTTP 的时间；超时显示 `SYNC TIMEOUT`。
首页长按下键不再打开赛历列表，短按上下键仍可浏览比赛。
车队积分直接读取 Jolpica 的车队积分榜及其调整，不通过车手分数相加推算。
与赛季后台任务一同自动刷新，使用独立离线缓存，最多保存 16 支车队。
首次完整下载前显示待更新；跨年后隐藏上一赛季车队积分，等待新赛季数据。
车手积分、车队积分及赛历任一请求失败，不会丢弃其他部分的有效缓存。

### 刷新资源

重复手动同步时显示真实剩余冷却秒数。一次串行刷新复用一个同站 HTTPS 客户端，
写缓存前或刷新结束时释放 TLS。PDKPASS 音频仅分配 TX/DAC；其他 BSP 使用者仍可通过
原来的全双工初始化接口录音。

私有存储、解析、积分、配网页及网络页面实现按
职责放入 `.inc` 文件，由所属服务包含。原来的任务和锁仍由同一服务持有，不增加后台任务。

### 独立于年份的赛道目录

离线目录收录 27 条赛道，包括波尔蒂芒、伊斯坦布尔公园、萨基尔和吉达。
稳定赛道 ID 将显示名称和别名统一映射到轮廓、长度、accent 和背景色，
跨赛季复用，不依赖上一赛季缓存。日期、场次、分节成绩和比赛圈数仍属于赛事数据。
圈数未知时显示 `-- LAPS`，但不再隐藏已知的赛道长度。

目录保存的是已有赛道布局，不代表未来认证已经完成。赛道发生实质改线时应使用
独立布局标识，而不是因为年份变化而覆盖历史轮廓。
没有手动赛季选择页面，赛季按有效设备时间自动选择。

### 赛道轮廓来源

内置 2026 赛道轮廓由创作者本机 Apex 赛道资源重新采样为 48 段紧凑坐标。该资源的
元数据注明：大多数赛道经 OpenF1 的 `circuit_info_url` 引用 MultiViewer，雪邦使用
OpenStreetMap 几何，Madring 参考其官方赛道图。PDKPASS 只内置重新采样后的坐标，不会
复制源 JSON、SVG 或地图作品。

OpenF1 将详细赛道信息标注为由
[MultiViewer](https://multiviewer.app/docs/)提供；雪邦几何归属
[OpenStreetMap 贡献者](https://www.openstreetmap.org/copyright)。当前用途是独立、非商业
车迷项目；如需商业分发，应先重新核对相关来源条款。

新增四条轮廓使用 MIT 许可的
[bacinger/f1-circuits](https://github.com/bacinger/f1-circuits) GeoJSON 数据，

## 在 macOS 上体验正式界面

仓库内置原生模拟器，直接运行与固件相同的 PDKPASS 页面、导航、分站主题、赛道轮廓、
积分榜和成绩布局。

```bash
git clone https://github.com/LeopardDennis/ai-passport-pdkpass.git
cd ai-passport-pdkpass
./tools/pdkpass-simulator/run.sh
```

使用 `--race 1` 至 `--race 23` 可以直接打开指定分站。键盘操作、无窗口截图和历史成绩
同步方法见[模拟器说明](tools/pdkpass-simulator/README.zh_CN.md)。

./tools/validate.sh --static
./tools/validate.sh --firmware

完整构建流程、刷机注意事项和 Recovery 保护要求见
[构建与测试说明](docs/development/build-and-test.zh_CN.md)。

## 可靠性

发布固件仅保留必要的警告和错误日志，不包含充电诊断采样、I2C 扫描、USB 截图任务、
运行过程日志或堆内存采样。电量显示仍使用电量计的真实读数，未修改充电或 SOC 参数。

记录的正赛结束后 30 分钟会再次检查积分，同步失败后间隔 5 分钟重试。
积分榜日期表示 Jolpica 对应分站日期（转换为北京时间），而非下载日期。
已发布的冲刺赛积分可能早于该站的正赛时间。当前周末优先于
历史数据补全；接口可用性和限流可能让数据发布晚于这些本地重试间隔。

HTTP、JSON 解析或内存分配失败时，保留简短错误记录，包含失败阶段、状态和错误码。
日志不输出请求网址、响应正文、Wi-Fi 密码或其他秘密。

每次进入配网会生成新的随机密码。正在测试连接时，请等待完成再提交另一组网络。
`NTP ERR` 表示 Wi-Fi 已连接，但仍在重试校时。本次开机已成功同步的时钟在
断线重连后继续可用；从 NVS 恢复的时间仅为离线估计，不包含断电经过的时间。
首页日期前的 `~` 表示估计时间；在成功校时前，不据此自动切换分站或赛季。

页面预览使用原生模拟器，真机画面可用照片记录。
熄屏后会停止 UI 空闲定时器；固件已配置自动轻睡眠，但 ADC 按键响应和实际
电池电流仍需实机验证。
